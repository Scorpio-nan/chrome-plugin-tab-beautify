## Project Structure & Module Organization

- `entrypoints/` — WXT entries (`background.ts`, `newtab/`, `popup/`, `options/`, `sidepanel/`); `wxt.config.ts` holds the manifest.
- `components/` — `nav/` sidebar, `grid/` tiles, `drawer/` add and edit, `settings/` panels, `ui/` vendored primitives.
- `widgets/` — one file per widget; `registry.tsx` is the only extension point.
- `lib/` — non-UI logic: `types`, `nav` (pure tree editors), `storage`, `hooks`.
- `assets/global.css` is the only stylesheet; `public/` holds icons and wallpapers generated by `scripts/`.

## Build, Test, and Development Commands

- `npm run dev` — dev server and watch build on port 4000.
- `npm run compile` — `tsc --noEmit`, the gate for every change.
- `npm run build` — emits `.output/chrome-mv3`; load it unpacked at `chrome://extensions`.
- `npm run zip` — store-ready archive; `npm run media` serves `assets/videos` for dynamic wallpapers.

## Coding Style & Naming Conventions

Two-space indent, single quotes, semicolons. Components `PascalCase.tsx`, lib modules `camelCase.ts`, hooks `useXxx`. Import through the `@/*` alias, never `../../`. Merge classes with `cn()` (`@/lib/utils`), prefer tokens like `bg-popover` over hex. Tailwind v4 keeps `scale`/`rotate`/`translate` separate: write `transition-[scale,rotate]`, not `transition-transform`, and keep arbitrary values literal. Comments are Chinese, no emoji in UI copy. No linter: match existing formatting and CRLF endings.

## Testing Guidelines

No test runner or coverage threshold: pass `npm run compile`, then verify in the loaded extension. Keep nav-tree edits as pure `lib/nav.ts` functions so they stay spot-checkable.

## Architecture & Interaction Rules

State lives only in `chrome.storage`: `sync` for `config`, `local` for the nav tree and icon data URLs (sync items cap at 8KB). Add preferences to `UserConfig` plus `DEFAULT_CONFIG`; `mergeConfig` tolerates older data. UI is a projection synced by `storage.onChanged`: settings apply live, no Apply buttons. Keep `useNav().update` reducers side-effect-free and generate ids outside them; fetch remote data in `background.ts` to avoid CORS. No hover action buttons: tiles, sidebar rows and canvas act through `components/ui/context-menu.tsx` (`MenuItem.submenu` cascades). `App.tsx` blocks the native menu; guard handlers with `isEditableTarget()` so paste works. Every drop zone reuses `drop-frame` and `.wetab-dwell-ring`; motion respects `prefers-reduced-motion`.

## Commit & Pull Request Guidelines

Nothing is binding; use Conventional Commits (`feat:`, `fix:`, `chore:`) with a short subject. PRs state what and why, link issues, and attach UI screenshots.
